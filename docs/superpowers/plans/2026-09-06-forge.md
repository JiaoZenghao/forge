# Forge V1 Implementation Plan

> For agentic workers: use superpowers:subagent-driven-development to implement and review independently testable tasks.

Goal: deliver the approved standalone Forge CLI with reproducible tests and cross-platform build artifacts.
Architecture: command adapters call a typed project model, generator orchestration, embedded standards, and offline validator. Subprocess and HTTP boundaries are injectable.
Tech stack: Go 1.25+, Cobra, Huh, yaml.v3, x/term, standard library.
Spec: ../specs/2026-09-06-forge-design.md

## Global constraints

- Implement create, doctor, describe, validate, version only.
- JSON mode emits exactly one object; child output goes to stderr; no input prompts.
- Never overwrite existing destinations or silently accept unsupported Java versions.
- Support Java 21, npm/Next.js, Maven/Spring Boot, optional uv/Python.
- Component paths are metadata fields, stored as slash-separated portable relative paths.
- Build CGO-free darwin/windows/linux binaries for amd64/arm64.
- Core functionality uses Go filesystem APIs and a centralized process runner.
